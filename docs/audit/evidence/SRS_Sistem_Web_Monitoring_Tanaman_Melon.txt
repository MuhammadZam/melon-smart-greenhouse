P103: Introduction
P104: Purpose
P105: Dokumen Software Requirement Specification (SRS) ini mendefinisikan secara formal, lengkap, dan terperinci seluruh kebutuhan fungsional, kebutuhan nonfungsional, arsitektur data, dan antarmuka eksternal dari Sistem Web Monitoring Tanaman Melon pada Greenhouse. Dokumen ini disusun sebagai artefak rekayasa perangkat lunak resmi untuk memenuhi kebutuhan akademik Computing Project lintas program studi pada Program Studi S-1 Informatika, Direktorat Kampus Surabaya, Universitas Telkom. Sistem ini dikembangkan melalui kolaborasi tripartit antara tim Informatika (perangkat lunak web, database, dan REST API), tim Teknik Elektro (perangkat keras IoT, firmware ESP32, sensor, dan aktuator), serta mitra industri/agronomi (penyedia wawasan budidaya melon dan standar panen). Spesifikasi dalam dokumen ini telah divalidasi dan disinkronkan secara ketat terhadap kode sumber aktual pada platform Laravel 11 dengan pencapaian baseline 119 automated test cases dan 5.935 assertions berstatus lolos 100%.
P106: Dokumen ini disusun berdasarkan Proposal Computing Project dan menjadi acuan bersama dalam perancangan, implementasi, pengujian, dan penerimaan sistem.

P116: Scope of the System
P117: Sistem Web Monitoring Greenhouse Melon adalah aplikasi web yang menjadi pusat pemantauan greenhouse melon. Fungsi utamanya adalah menerima data sensor dari ESP32 melalui REST API, menyimpannya secara terpusat, lalu menampilkan kondisi terkini, alarm, grafik tren, dan riwayat. Sistem juga mengelola data tanaman (blok/batch) serta mencatat ukuran dan kematangan buah yang dapat dibandingkan dengan kondisi lingkungan.
P118: Pengguna utama sistem adalah Admin, yang mengelola data tanaman, pengamatan buah, akun, dan batas parameter, serta Pengamat Lapangan (User), yang melihat dashboard, alarm, grafik, dan riwayat. Seluruh pengguna wajib login.
P119: Manfaat sistem adalah data budidaya melon tersimpan terpusat dan terstruktur, kondisi abnormal cepat diketahui melalui status warna dan alarm, serta perkembangan tanaman dan buah dapat dievaluasi melalui grafik dan riwayat. Pengembangan perangkat keras, firmware, dan logika kontrol ESP32 berada di luar lingkup sistem ini karena dikerjakan tim Elektro.
P120: Overall Description
P121: Product Perspective
P122: Sistem merupakan aplikasi web yang berdiri sendiri pada sisi aplikasi, tetapi terintegrasi dengan subsistem IoT milik tim Elektro melalui REST API. ESP32 mengirim data sensor ke sistem, sedangkan seluruh logika kontrol (termasuk logika fuzzy) tetap berada di ESP32. Web hanya menampilkan hasilnya dan, bila disepakati, mengirim perintah override. Gambar 1 menunjukkan diagram konteks sistem.
P124: Gambar 1. Diagram konteks sistem
P125: Arsitektur sistem terdiri dari sisi greenhouse (sensor, ESP32, aktuator), server aplikasi Laravel 11 dengan basis data MySQL, dan browser pengguna. Alur dasarnya: (1) ESP32 mengirim data sensor ke REST API; (2) Laravel memvalidasi, menyimpan ke MySQL, dan mengevaluasi batas untuk membuat alarm; (3) pengguna login melalui browser; (4) data ditampilkan pada dashboard, grafik, riwayat, dan daftar alarm.

P244: Regulasi: data pribadi pengguna dibatasi pada nama dan email, dikelola dengan mengacu pada UU No. 27 Tahun 2022 tentang Pelindungan Data Pribadi (minimisasi data dan perlindungan password).

P247: Aturan keamanan: login wajib, pembatasan akses berdasarkan role, token API untuk perangkat, validasi input, dan password ter-hash.
P248: Logika kontrol: web tidak menghitung logika kontrol atau fuzzy; hanya menampilkan hasilnya dan, bila disepakati, mengirim perintah override.

P250: Skala: pengujian dilakukan pada skala prototype dan periode terbatas.

P1050: Non-Functional Requirements (NFR)

P1052: Performance Requirements
P1053: NFR-P1 (Response time): halaman dashboard dan daftar data dimuat dalam 3 detik atau kurang untuk 95% permintaan pada koneksi normal.
P1054: NFR-P2 (Grafik): grafik dengan rentang hingga 30 hari tampil dalam 5 detik atau kurang dengan memanfaatkan data yang telah diringkas.
P1055: NFR-P3 (API): endpoint POST /api/monitorings merespons dalam 1 detik atau kurang.
P1056: NFR-P4 (Throughput): sistem mampu menerima minimal 60 permintaan API per menit tanpa kehilangan data.
P1057: NFR-P5 (Concurrent users): sistem melayani minimal 20 pengguna bersamaan tanpa penurunan kinerja berarti (skala prototype).
P1058: Security Requirements
P1059: NFR-S1 (Autentikasi): login wajib; password disimpan dalam bentuk hash.
P1060: NFR-S2 (Otorisasi): pembatasan akses berdasarkan role diterapkan di sisi server pada setiap halaman dan aksi.
P1061: NFR-S3 (Token API): token perangkat disimpan ter-hash, dapat dicabut, dan permintaan tanpa token valid ditolak.
P1062: NFR-S4 (Enkripsi): seluruh komunikasi pengguna dan perangkat menggunakan HTTPS.
P1063: NFR-S5 (Proteksi aplikasi): perlindungan terhadap CSRF, XSS, dan SQL injection, serta pembatasan laju (rate limiting) pada login dan API.
P1064: NFR-S6 (Logging): sistem mencatat login gagal, perubahan data master, dan tindakan override aktuator (siapa dan kapan).
P1065: NFR-S7 (Compliance): pengelolaan data pribadi mengacu pada UU No. 27 Tahun 2022 (PDP) dengan data pribadi minimal.
P1066: Usability Requirements
P1067: NFR-U1 (Responsif): tampilan menyesuaikan layar laptop, tablet, dan ponsel.
P1068: NFR-U2 (Bahasa): antarmuka berbahasa Indonesia dengan istilah yang konsisten.
P1069: NFR-U3 (Aksesibilitas): status tidak hanya dibedakan warna, tetapi juga label teks atau ikon; kontras teks mengikuti WCAG 2.1 level AA (minimal 4,5:1).
P1070: NFR-U4 (Umpan balik): pesan kesalahan jelas dan penghapusan data memerlukan konfirmasi.
P1071: NFR-U5 (Kemudahan penggunaan): status sensor dan alarm dapat dilihat langsung pada dashboard; target skor UAT minimal 85%.
P1072: Reliability Requirements
P1073: NFR-R1 (Availability): ketersediaan sistem minimal 95% selama periode pengujian.
P1074: NFR-R2 (Fault tolerance): kegagalan satu permintaan API tidak memengaruhi data lain; respons error terstruktur agar ESP32 dapat mengirim ulang; pengiriman ganda untuk tanaman dan waktu pengukuran yang sama tidak disimpan dua kali.
P1075: NFR-R3 (Backup & recovery): pencadangan basis data berkala (minimal harian) dengan prosedur pemulihan yang terdokumentasi.
P1076: NFR-R4 (Integritas data): relasi antar tabel dijaga dengan foreign key dan transaksi basis data.
P1077: Maintainability Requirements
P1078: NFR-M1 (Coding standard): mengikuti PSR-12 dan konvensi Laravel; kode dikelola di GitHub.
P1079: NFR-M2 (Dokumentasi): tersedia SRS, SDD, spesifikasi API, dan User Guide.
P1080: NFR-M3 (Pengujian otomatis): pengujian PHPUnit/Pest untuk autentikasi, API, dan logika alarm.
P1081: NFR-M4 (Konfigurasi): batas parameter disimpan di basis data sehingga dapat diubah tanpa mengubah kode.
P1082: Portability Requirements
P1083: NFR-PO1 (Multi-platform): dapat diakses pada browser modern di Windows, macOS, Linux, Android, dan iOS.
P1084: NFR-PO2 (Deployment): dapat dipasang pada Railway, VPS, atau hosting kampus melalui konfigurasi lingkungan (.env) tanpa mengubah kode.
