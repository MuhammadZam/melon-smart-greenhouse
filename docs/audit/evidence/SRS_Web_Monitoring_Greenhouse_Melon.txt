P95: Introduction
P96: Purpose
P97: Dokumen Software Requirement Specification (SRS) ini mendefinisikan kebutuhan fungsional, nonfungsional, dan antarmuka dari Aplikasi Web Monitoring Greenhouse Melon. Aplikasi ini dikembangkan oleh tim Informatika dalam Computing Project lintas program studi bersama tim Elektro dan tim Logistik, dan digunakan oleh Admin serta Pengamat Lapangan untuk memantau kondisi greenhouse melon dan mencatat perkembangan buah.
P98: Dokumen ini disusun berdasarkan Proposal Computing Project dan menjadi acuan bersama dalam perancangan, implementasi, pengujian, dan penerimaan sistem.
P99: Intended Readers
P100: Dokumen ini ditujukan bagi pihak berikut:
P101: Project manager: memantau kesesuaian lingkup, jadwal, dan kesepakatan lintas tim.
P102: Analyst: menjadi dasar penyusunan SDD, ERD, dan spesifikasi API.
P103: Developer (front-end dan back-end): acuan implementasi fitur, basis data, dan REST API.
P104: QA/tester: dasar penyusunan skenario uji fungsional, API, alarm, integrasi, dan UAT.
P105: Tim Elektro: acuan kontrak API, format data sensor, dan antarmuka perangkat keras.
P106: Tim Logistik: acuan kebutuhan lingkungan operasi untuk perencanaan pengadaan.
P107: Stakeholder (dosen pembimbing dan kampus): memahami cakupan dan kebutuhan sistem.
P108: Scope of the System
P109: Sistem Web Monitoring Greenhouse Melon adalah aplikasi web yang menjadi pusat pemantauan greenhouse melon. Fungsi utamanya adalah menerima data sensor dari ESP32 melalui REST API, menyimpannya secara terpusat, lalu menampilkan kondisi terkini, alarm, grafik tren, dan riwayat. Sistem juga mengelola data tanaman (blok/batch) serta mencatat ukuran dan kematangan buah yang dapat dibandingkan dengan kondisi lingkungan.
P110: Pengguna utama sistem adalah Admin, yang mengelola data tanaman, pengamatan buah, akun, dan batas parameter, serta Pengamat Lapangan (User), yang melihat dashboard, alarm, grafik, dan riwayat. Seluruh pengguna wajib login.
P111: Manfaat sistem adalah data budidaya melon tersimpan terpusat dan terstruktur, kondisi abnormal cepat diketahui melalui status warna dan alarm, serta perkembangan tanaman dan buah dapat dievaluasi melalui grafik dan riwayat. Pengembangan perangkat keras, firmware, dan logika kontrol ESP32 berada di luar lingkup sistem ini karena dikerjakan tim Elektro.
P112: Overall Description
P113: Product Perspective
P114: Sistem merupakan aplikasi web yang berdiri sendiri pada sisi aplikasi, tetapi terintegrasi dengan subsistem IoT milik tim Elektro melalui REST API. ESP32 mengirim data sensor ke sistem, sedangkan seluruh logika kontrol (termasuk logika fuzzy) tetap berada di ESP32. Web hanya menampilkan hasilnya dan, bila disepakati, mengirim perintah override. Gambar 1 menunjukkan diagram konteks sistem.
P116: Gambar 1. Diagram konteks sistem
P117: Arsitektur sistem terdiri dari sisi greenhouse (sensor, ESP32, aktuator), server aplikasi Laravel 11 dengan basis data MySQL, dan browser pengguna. Alur dasarnya: (1) ESP32 mengirim data sensor ke REST API; (2) Laravel memvalidasi, menyimpan ke MySQL, dan mengevaluasi batas untuk membuat alarm; (3) pengguna login melalui browser; (4) data ditampilkan pada dashboard, grafik, riwayat, dan daftar alarm.

P227: Operating Environment
P228: Sistem beroperasi pada lingkungan berikut:
P229: Platform: aplikasi web responsif untuk laptop, tablet, dan ponsel; tidak mencakup aplikasi mobile native.
P230: Sistem operasi klien: Windows, macOS, Linux, Android, dan iOS selama memiliki browser modern.
P231: Browser: versi terbaru Google Chrome, Microsoft Edge, Mozilla Firefox, dan Safari.
P232: Server/hosting: Railway, VPS, atau hosting kampus dengan PHP 8.2, Laravel 11, MySQL, web server (Nginx atau Apache), dan HTTPS.
P233: Perangkat IoT: ESP32 dengan koneksi WiFi dan internet di lokasi greenhouse.
P234: Kebutuhan AI/ML: tidak ada; sistem tidak mencakup analisis prediksi.
P235: Design and Implementation Constraints
P236: Regulasi: data pribadi pengguna dibatasi pada nama dan email, dikelola dengan mengacu pada UU No. 27 Tahun 2022 tentang Pelindungan Data Pribadi (minimisasi data dan perlindungan password).
P237: Hardware/software: pengembangan perangkat keras, firmware, sensor, dan logika kontrol ESP32 berada di luar lingkup tim Informatika; pengiriman data bergantung pada WiFi dan internet di greenhouse; data pH dan EC/TDS menyusul sesuai kesiapan sensor.
P238: Framework: Laravel 11 (PHP 8.2) sebagai framework full stack dengan Blade, Tailwind CSS, Alpine.js, Chart.js, dan MySQL (Eloquent ORM).
P239: Aturan keamanan: login wajib, pembatasan akses berdasarkan role, token API untuk perangkat, validasi input, dan password ter-hash.
P240: Logika kontrol: web tidak menghitung logika kontrol atau fuzzy; hanya menampilkan hasilnya dan, bila disepakati, mengirim perintah override.
P241: Modul aktuator: bergantung pada keputusan tim Elektro; bila belum diputuskan, modul ditunda tanpa mengganggu fitur inti.
P242: Skala: pengujian dilakukan pada skala prototype dan periode terbatas.
P243: Assumptions and Dependencies
P244: Asumsi
P245: ESP32 mengirim data secara periodik dengan interval dan format yang disepakati bersama tim Elektro dalam kontrak API.
P246: Setiap data sensor berkaitan dengan satu tanaman (blok/batch) terdaftar, dan ESP32 mengetahui plant_id yang sesuai.
P247: Batas awal parameter dari tim Elektro dianggap valid dan dapat diubah Admin.
P248: Bila koneksi terputus, data pada periode tersebut tidak masuk dan kondisi ini ditandai melalui alarm data berhenti masuk.
P249: Pengguna memiliki perangkat dan browser modern serta koneksi internet.
P251: Dependensi eksternal
P252: Tim Elektro: perangkat ESP32, sensor, aktuator, kontrak API, token perangkat, dan keputusan mode aktuator.
P253: Tim Logistik: perencanaan kebutuhan dan pengadaan komponen.
P254: Layanan hosting (Railway/VPS/hosting kampus) beserta HTTPS.
P255: Pustaka pihak ketiga: Laravel, Tailwind CSS, Alpine.js, dan Chart.js.

P669: Non-Functional Requirements (NFR)
P670: Nilai target pada bagian ini merupakan usulan awal tim dan dapat disesuaikan setelah pengujian performa serta kesepakatan dengan dosen pembimbing.
P671: Performance Requirements
P672: NFR-P1 (Response time): halaman dashboard dan daftar data dimuat dalam 3 detik atau kurang untuk 95% permintaan pada koneksi normal.
P673: NFR-P2 (Grafik): grafik dengan rentang hingga 30 hari tampil dalam 5 detik atau kurang dengan memanfaatkan data yang telah diringkas.
P674: NFR-P3 (API): endpoint POST /api/monitorings merespons dalam 1 detik atau kurang.
P675: NFR-P4 (Throughput): sistem mampu menerima minimal 60 permintaan API per menit tanpa kehilangan data.
P676: NFR-P5 (Concurrent users): sistem melayani minimal 20 pengguna bersamaan tanpa penurunan kinerja berarti (skala prototype).
P677: Security Requirements
P678: NFR-S1 (Autentikasi): login wajib; password disimpan dalam bentuk hash.
P679: NFR-S2 (Otorisasi): pembatasan akses berdasarkan role diterapkan di sisi server pada setiap halaman dan aksi.
P680: NFR-S3 (Token API): token perangkat disimpan ter-hash, dapat dicabut, dan permintaan tanpa token valid ditolak.
P681: NFR-S4 (Enkripsi): seluruh komunikasi pengguna dan perangkat menggunakan HTTPS.
P682: NFR-S5 (Proteksi aplikasi): perlindungan terhadap CSRF, XSS, dan SQL injection, serta pembatasan laju (rate limiting) pada login dan API.
P683: NFR-S6 (Logging): sistem mencatat login gagal, perubahan data master, dan tindakan override aktuator (siapa dan kapan).
P684: NFR-S7 (Compliance): pengelolaan data pribadi mengacu pada UU No. 27 Tahun 2022 (PDP) dengan data pribadi minimal.
P685: Usability Requirements
P686: NFR-U1 (Responsif): tampilan menyesuaikan layar laptop, tablet, dan ponsel.
P687: NFR-U2 (Bahasa): antarmuka berbahasa Indonesia dengan istilah yang konsisten.
P688: NFR-U3 (Aksesibilitas): status tidak hanya dibedakan warna, tetapi juga label teks atau ikon; kontras teks mengikuti WCAG 2.1 level AA (minimal 4,5:1).
P689: NFR-U4 (Umpan balik): pesan kesalahan jelas dan penghapusan data memerlukan konfirmasi.
P690: NFR-U5 (Kemudahan penggunaan): status sensor dan alarm dapat dilihat langsung pada dashboard; target skor UAT minimal 85%.
P691: Reliability Requirements
P692: NFR-R1 (Availability): ketersediaan sistem minimal 95% selama periode pengujian.
P693: NFR-R2 (Fault tolerance): kegagalan satu permintaan API tidak memengaruhi data lain; respons error terstruktur agar ESP32 dapat mengirim ulang; pengiriman ganda untuk tanaman dan waktu pengukuran yang sama tidak disimpan dua kali.
P694: NFR-R3 (Backup & recovery): pencadangan basis data berkala (minimal harian) dengan prosedur pemulihan yang terdokumentasi.
P695: NFR-R4 (Integritas data): relasi antar tabel dijaga dengan foreign key dan transaksi basis data.
P696: Maintainability Requirements
P697: NFR-M1 (Coding standard): mengikuti PSR-12 dan konvensi Laravel; kode dikelola di GitHub.
P698: NFR-M2 (Dokumentasi): tersedia SRS, SDD, spesifikasi API, dan User Guide.
P699: NFR-M3 (Pengujian otomatis): pengujian PHPUnit/Pest untuk autentikasi, API, dan logika alarm.
P700: NFR-M4 (Konfigurasi): batas parameter disimpan di basis data sehingga dapat diubah tanpa mengubah kode.
P701: Portability Requirements
P702: NFR-PO1 (Multi-platform): dapat diakses pada browser modern di Windows, macOS, Linux, Android, dan iOS.
P703: NFR-PO2 (Deployment): dapat dipasang pada Railway, VPS, atau hosting kampus melalui konfigurasi lingkungan (.env) tanpa mengubah kode.
P704: Data Requirements
P705: Bagian ini menjabarkan struktur data sistem berupa ERD, kamus data, serta batas parameter dan aturan alarm.
